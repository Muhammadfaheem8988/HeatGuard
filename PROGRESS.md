## Project Summary

HeatGuard Alerts is a vulnerability-targeted heat early-warning system built for the FortyGuard Hackathon '26 (Track 04: Government & Public Policy). It fuses hyperlocal temperature data from the FortyGuard API (`/v1/heatmap`, `/v1/env_params`) with public vulnerability data (CDC PLACES / Census ACS at the census-tract level) to produce a ranked, explainable "top 10 highest-risk blocks" list for a real U.S. city. The system simulates targeted, plain-language SMS-style alerts generated by the Google Gemini API (with a static fallback), displayed in a Streamlit dashboard (map + ranked list + alert feed). The core insight: a city-wide heat warning tells everyone "it's hot" — HeatGuard tells emergency managers *which 10 blocks* need a wellness check today, and *why*.

## Key Decisions & Why

| Decision | Rationale |
|---|---|
| Streamlit over React/FastAPI | Fastest path to deployable dashboard. PRD explicitly recommends it. |
| Phoenix AZ as primary test city | Heat-relevant, large coverage, PRD recommended. Houston is backup. Locked AFTER first successful API call. |
| Historical date (not today) | PRD Section 8.1 documents confirmed empty-tile bug for current/recent requests. Target: 2024-07-15 Phoenix. |
| filter_type=3 (full day) | Gets diurnal curve; more useful for scoring. Pull once, cache. |
| 100m granularity for first test | Coarser = fewer tiles = lower credit cost for validation. |
| Vulnerability proxy for no-AC | ACS has no direct "no AC" variable. Will use B25040 or pre-1980 housing proxy. Decision in Hr 2–5. |
| Cache-first architecture | Every successful API response cached to cache/ as JSON. Never re-request same combo. |
